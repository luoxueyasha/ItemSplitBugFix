# Item Split Bug Fix

**This mod fixes the item split bug.**

* CurseForge:https://legacy.curseforge.com/minecraft/mc-mods/item-split-bug-fix
* Twitter: https://twitter.com/iwaliner_MC

## Usage

In some cases (wrong code, code generator...), a blank NBT tag will be added to an Itemstack, so this stack will not stack with other stacks.  
This mod solves the problem (in most cases).

### Blacklists
If you are facing issues around this mod, you can either
  * [post an issue on github](https://github.com/iwaliner/ItemSplitBugFix-1.20.1/issues) _(don't forget your logs!)_
  * or use the mod's **blacklist config.**

The blacklist should contain items you don't want to be modified(mixined) by this mod.  
By default it's in `.minecraft/config/ItemSplitBugFix.toml`.  
Example:
```toml
[blacklist_settings]
	# Items in this list will not be modified by ItemSplitBugFix.
	# Supports wildcard '*'.
	blacklist = ["alexscaves:sack_of_sating", "hexerei:*", "spelunkery:*",
                 "minecraft:spyglass", "technicalcores:*", #default blacklist
                 "your_item:*","*your:another_*_item"]
```

### What about the older versions like 1.12.2 or 1.7.10?
Depends on if the project toolchain supports these versions. Currently, we will test if 1.19.2 is stable, and if it is, maybe we will take the port. Stay calm.  

### and... what about Fabric and NeoForge?
Fabric port is not on schedule yet.  
For NeoForge, as it aims 1.21+, which item NBT API changes a lot; the split bug *should* not occur, theoretically.  
However the deprecated code and toolchain works fine, so we just leave it here, comment them out, for someday in the future.

## Building the Project

This project is based on template generated by [universal-mod-template-generator](https://github.com/Ran-Mewo/universal-mod-template-generator) by Ran-Mewo.
As you may see, the template is a multi-version template based on [Unimined](https://github.com/unimined/unimined), so this will be little tricky than normal forge projects.

To switch target variant, set variable `mc_ver` in `gradle.properties`.
* Needs a gradle sync after switching variants
* You have to switch versions manually when building each version. The results will be under `common\build\libs\`.
  * Yes, you may also write a gradle script for building ALL `mc_ver`s.
  * **DO NOT TOUCH build.properties**. This is an auto-generated file and your changes could be lost.
  
To run the game, use `Gradle -> forge -> Tasks -> unimined_runs -> runClient`. 

[//]: # (or `Gradle -> neoforge -> Tasks -> unimined_runs -> runClient` )

[//]: # (depending on which version you are on.)

To configure each version, see `versionProperties\<minecraft version>.properties`.

Also you may notice the gradle scripts changed a lot. The gradle scripts are under `buildSrc\src\main\groovy\`. You may need [Unimined docs](https://github.com/unimined/Unimined/tree/lts/1.4/Writerside/topics) for changes.

## Contributing

This project uses Unimined Fabric toolchain for Mixin. Please do not remove Fabric declarations unless you know what you are doing.

[Manifold](https://github.com/manifold-systems/manifold) is a gradle plugin for switching different variants on Java. You could use C-like `#if` and `#ifdef` before compiling.
* If you are using Intellj IDEA, install [Manifold Plugin](https://plugins.jetbrains.com/plugin/10057-manifold-ij) for better experience. Example:
```java
int myfunc() {
#if MC_VER == MC_1_20_1
    // code for 1.20.1
#elif MC_VER == MC_1_19_2
    // code for 1.19.2
#endif
}
```
